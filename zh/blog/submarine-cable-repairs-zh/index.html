海底光缆维修：为什么国外网站会突然变慢？

✨ NetBijak AI 智能摘要

当你发现马来西亚本地网络运行正常，但访问海外网站出现延迟或卡顿时，问题往往并非出在你家的光纤接入上，而是源于上游国际海底光缆的故障或维修。当海底光缆受损时，运营商会进行重新路由，将流量转移至其他备用线路，这可能导致路径变长或备用带宽拥堵。这种情况下，即使本地测速显示速度达标，海外访问依然会因为丢包和延迟增加而变得缓慢。此外，由于不同网站使用的国际路径及CDN节点各异，海底光缆故障对不同服务的影响程度往往不同。因此，建议用户通过对比不同国家和地区的访问表现进行初步排查，盲目升级家用宽带带宽并不能缓解国际线路的拥堵问题。若确认为国际网络故障，重启路由器等本地操作通常无效，建议关注运营商的官方公告。

如果你发现 马来西亚本地网站正常，但美国、日本或其他海外网站突然变慢，问题不一定出在你家的 Fibre Broadband。

国际海底光缆发生故障或进行维修时，ISP 可用的国际传输容量可能减少。ISP 会把流量转移到其他国际路线，但备用路线可能更长，也可能更加拥堵，因此用户仍然会感受到明显的延迟或速度下降。

为什么马来西亚需要依赖海底光缆？

你的家用 Fibre 并不是直接连接到全球 Internet。

当你访问海外服务器时，数据通常会先经过 ISP 的本地网络，再进入国际网络，最后通过一条或多条海底光缆前往其他国家。

简单来说，一次连接可能经过：

你的家 → ISP 网络 → 国际 Gateway → 海底光缆 → 海外网络 → 目标服务器

如果你访问的是马来西亚本地服务器，流量可能主要留在国内网络。

但如果你访问的是美国、日本或欧洲的服务器，数据就必须经过国际网络。

因此，本地网站正常、海外网站变慢，并不矛盾。

问题可能根本不在你家的 Fibre，而是在 ISP 更上游的国际连接。

海底光缆出问题后，会发生什么？

海底光缆故障并不代表整个 ISP 会马上断网。

更常见的情况是：

某条国际路线的可用容量减少。

大型 ISP 通常不会只依赖一条国际路线。当其中一条 Cable 出现故障时，网络运营商可以把流量转移到其他可用路径。

这就是我们常说的 Rerouting（重新路由）。

例如原本可能是：

Malaysia → International Gateway → Cable A → Overseas Transit → Server

Cable A 出现问题后：

Malaysia → International Gateway → Cable B → Overseas Transit → Server

用户仍然可以连接到服务器，但 Cable B 的路线可能更长，或者剩余容量没有 Cable A 那么充足。

所以：

Cable 坏了 ≠ Internet 一定断掉。

但：

Rerouting 也 ≠ 原来的速度和延迟完全不变。

APCN2 和 AAG：马来西亚过去就发生过类似情况

马来西亚的国际网络曾受到包括 APCN2 和 AAG 等海底光缆系统故障或维修的影响。

APCN2

Asia Pacific Cable Network 2（APCN2） 是连接亚洲多个主要电信市场的国际海底光缆系统。

在 APCN2 出现故障时，TM 曾表示其国际容量受到影响，但通过其他国际路线进行重新路由和优化，以维持服务。

这其实很好地解释了为什么海底光缆断了，用户却没有完全断网。

原本的 Cable 出问题，但流量被转移到其他路线。

真正的问题变成：备用路线有没有足够容量。

AAG

Asia-America Gateway（AAG） 是连接东南亚与包括美国、香港等地区的重要海底光缆系统。

过去 AAG 进行维修时，TM 曾提醒用户，依赖相关国际路线的部分服务可能出现性能下降，同时会把流量转移到其他路线，以减少影响。

所以你会发现，ISP 的 Cable Maintenance 公告通常不会简单写：

“整个 Internet 会变慢。”

因为实际影响取决于哪一条路线受到影响，以及你的流量原本走哪里。

ISP 的 Rerouting 到底是怎么工作的？

这里真正值得理解的，并不是“ISP 找另一条 Cable”这么简单。

Internet 是由大量不同的网络组成，而这些网络之间需要交换路由信息。

在大型 Internet 网络层面，其中一个核心机制就是 BGP（Border Gateway Protocol）。

BGP 用来告诉其他网络：

“哪些 IP Prefix 可以通过我这里到达，以及应该经过什么路径。”

当某条国际路线不可用或网络运营商需要调整流量时，相关路由信息可以发生变化，让流量转向另一条可用路径。

对普通用户来说，可以把它理解为：

目的地没有变，但去目的地的路线变了。

而路线改变之后，最容易受到影响的是三个东西：

Latency

备用路线可能更长，或者经过更多 Network Hops，因此 Ping 增加。

Packet Loss

如果大量流量被挤到备用路线，而备用路线出现拥堵，就可能产生 Packet Loss。

Throughput

TCP 连接检测到丢包或拥塞后，会降低传输速率。

因此，即使你的 Fibre 本身拥有 500Mbps 或 1Gbps 的本地带宽，某个海外下载仍然可能非常慢。

问题不一定是你家的 Fibre Speed 不够，而可能是通往目标服务器的国际路径出现拥塞或丢包。

为什么 Rerouting 后 Internet 还是会变慢？

假设原本的国际路线还有大量空余容量。

一旦某条海底光缆停止服务，原本经过这条 Cable 的流量必须转移到其他路线。

如果备用路线容量足够，普通用户可能几乎感觉不到变化。

但如果大量流量集中到容量有限的路线，就会开始出现拥塞。

这也是为什么 Cable Incident 经常出现一种很奇怪的情况：

凌晨很正常，晚上却特别慢。

因为国际路线在高峰时段本来就有更多流量。

因此，Cable Fault 的表现可能是：

  1. Singapore 网站正常
  2. US 网站很慢
  3. Japan Server Ping 增加
  4. Gaming 延迟突然升高
  5. VPN 连接变得不稳定
  6. 海外下载速度明显下降

这并不一定代表你的 Fibre 本身出现故障。

为什么只有某些网站变慢？

这是判断问题位置时非常重要的一点。

海底光缆故障不会平均影响所有网站。

原因包括：

不同网站使用不同路线

新加坡、日本和美国服务器可能完全使用不同的国际路径。

因此一个国家的服务正常，并不能证明另一个国家的路线也正常。

网站可能使用 CDN

大型平台通常会使用 Content Delivery Network（CDN）。

如果你访问的内容已经缓存到比较靠近马来西亚的节点，就不一定需要一直连接到美国或欧洲的 Origin Server。

所以即使某条跨洲海底光缆出现问题，使用附近 CDN 的服务仍可能运行正常。

不同 ISP 的国际连接不同

即使两个人住在同一个地区，不同 ISP 也可能拥有不同的国际 Upstream 或 Transit 路线。

一个 ISP 可能已经把流量成功转移到比较空闲的路线，而另一个 ISP 的备用路线可能更加拥堵。

所以：

朋友的 ISP 正常，不代表你的 Fibre 一定坏了。

为什么 Speed Test 还是可以跑到 500Mbps？

这是消费者最容易误判的地方之一。

Speed Test 测试的并不是一个叫做 “整个 Internet” 的东西。

它测试的是：

你的设备 → ISP → 指定 Speed Test Server

如果这个测试服务器位于马来西亚，或者你的 ISP 与该服务器之间拥有良好的本地 Peering，那么测试流量根本不需要经过发生问题的国际路线。

所以完全可能出现：

Malaysia Speed Test：500Mbps

同时：

US Website：非常慢

这两个结果并不冲突，因为它们走的是不同的 Network Path。

如果要判断是不是国际网络问题，可以比较不同目的地：

  1. Malaysia
  2. Singapore
  3. Hong Kong
  4. Japan
  5. United States

如果本地速度正常，但多个海外目的地出现明显较高的 Latency 或 Packet Loss，就更值得怀疑国际路线。

想进一步确认？可以用 Traceroute

如果你对网络技术比较熟悉，Traceroute 比单纯看 Speed Test 更有参考价值。

Windows 可以使用：

tracert example.com

macOS 或 Linux：

traceroute example.com

它会显示你的设备到目标服务器之间经过的 Network Hops。

不过不要犯一个常见错误：

看到某一个 Hop 显示 Packet Loss，就直接认定那个 Router 坏了。

部分 Router 本来就可能限制或忽略 ICMP 回应，因此中间某个 Hop 显示丢包，并不一定代表最终连接真的丢包。

更有意义的是看整体路径变化。

例如：

Malaysia → ISP Network → International Gateway → Singapore → US → Destination

如果你发现某个海外目标突然走了完全不同的路径，或者离开 Malaysia 后 Latency 明显增加，这就是比较有价值的线索。

最好同时：

  1. 测试不同海外目的地
  2. 不同时间测试
  3. 比较不同网络

这样比单独跑一次 Traceroute 更有意义。

为什么 Packet Loss 有时比速度下降更严重？

很多用户只看 Mbps，但对于国际连接来说，Latency 和 Packet Loss 同样重要，甚至可能更加明显。

TCP 发现 Packet Loss 后，会认为网络可能存在拥塞或传输问题，并降低发送速度。

因此，即使只有一定程度的持续丢包，也可能明显影响长距离 TCP 连接。

例如你的 Fibre 本地仍然拥有数百 Mbps 的容量，但从 Malaysia 到美国的国际路径出现拥塞和 Packet Loss，那么：

本地 Fibre 速度很快 ≠ 美国服务器下载速度一定快。

这对于以下服务尤其明显：

  1. Cloud Services
  2. International File Downloads
  3. Remote Desktop
  4. VPN
  5. Online Gaming
  6. Video Conferencing

换 ISP 可以解决海底光缆问题吗？

有可能，但绝对不是保证。

关键不是 Broadband Bill 上写着哪个品牌，而是：

这个 ISP 实际上通过什么国际网络到达你的目标服务器。

两个不同的 ISP 可能使用不同的国际路线。

反过来，两个看起来完全不同的 Broadband Service，也可能在某些地方共享相同的 Upstream、Transit 或 Cable Capacity。

因此，如果问题是国际路线拥塞，单纯从：

300Mbps → 500Mbps → 1Gbps

并不会自动解决问题。

如果 Bottleneck 位于国际网络，你增加的是家里的 Access Capacity，而不是那条国际路线的容量。

海底光缆维修需要多久？

没有一个统一的维修时间。

海底光缆维修需要专业的海上维修船只和设备，时间可能受到以下因素影响：

  1. 故障位置
  2. 海况与天气
  3. Repair Vessel 是否可用
  4. 能否进入故障区域
  5. Spare Cable 是否充足
  6. 受影响的 Cable Segment 数量
  7. Cable Owners / Operators 之间的协调

但这里有一个重要区别：

Physical Repair Time ≠ Customer Impact Time

ISP 不一定要等海底光缆实际修好之后，用户的 Internet 才能恢复正常。

如果 ISP 成功把流量转移到其他路线，用户的体验可能在 Cable 完全维修之前就已经改善。

反过来，一条 Cable 即使没有完全断掉，在维修期间降低可用容量，也可能造成拥塞。

怎么判断是家里的 Fibre 还是国际网络出了问题？

不要只看一次 Speed Test，而是看问题出现的模式。

你遇到的情况比较可能的原因
马来西亚和海外网站全部变慢WiFi、Router、Fibre、Access Network 或 ISP 问题
本地网站正常，部分海外网站很慢International Routing / Destination 问题
多个海外国家的 Latency 都突然升高国际连接问题
只有一个网站很慢网站服务器、CDN 或网站本身的问题也可能
不同 ISP 的表现明显不同International Routing / Upstream 不同
Speed Test 正常，但海外下载很慢International Congestion、Packet Loss 或 Server 限制

这不是专业网络工程师的最终诊断，但足以帮助普通用户避免一个最常见的错误：

海外网站慢，就马上怪自己的 Fibre。

海底光缆出现故障时，马来西亚用户应该怎么办？

如果 ISP 已经确认是 International Cable Fault 或 Maintenance，而你家里的本地连接没有其他问题，就没有必要一直重复 Restart ONT 或 Router。

更有效的方法是确认：

  1. 马来西亚本地服务是否正常
  2. 哪些海外网站受到影响
  3. 不同国家的 Server 是否表现不同
  4. Latency 有没有明显增加
  5. 是否出现 Packet Loss
  6. ISP 有没有发布 International Network Incident 公告

如果联系 ISP，也不要只说：

“我的 Internet 很慢。”

最好提供：

  1. 哪个网站
  2. 哪个时间段
  3. 目标国家
  4. Ping / Latency
  5. Traceroute 结果

这些资料对判断问题发生在哪里更有帮助。


NetBijak’s Take

海底光缆故障，不等于你家的 Fibre 坏了。

真正需要判断的是问题发生在哪里：可能是本地 WiFi，也可能是 ISP Access Network，更可能是通往某个海外目的地的 International Route。

如果马来西亚本地服务正常，但特定海外网站突然出现高 Latency、Packet Loss 或明显的 Throughput 下降，那么在升级 Fibre 配套之前，先检查 International Routing。

500Mbps 还是 1Gbps，解决不了一条正在拥堵的国际路线。
